# 2026-11-11 worklog

## 1. v0.2: fleet loop, following DHH's multi-agent workflow
- Goal (from user): improve orchard with the harness conventions (github.com/qhan2012/harness) and DHH's way of running many agents.
- Ground truth for DHH's workflow: Lex Fridman Podcast #501 transcript (https://lexfridman.com/dhh-2-transcript), chapters "Programming setup for AI Agents" (~1:31:46) and "Best AI coding harnesses" (~2:37:55). Points used:
  - herdr is "tmux plus agent notifications": a bell when an agent needs a decision, a mark when it works. He runs it on several machines.
  - He supervises about 16 threads at full speed. The person is the bottleneck.
  - One model builds (Opus/Fable), a different model reviews (Codex xHigh). He calls this his standard procedure.
  - A scheduled bot ("Oma bot") handles issues and PRs and emails him a summary. He makes the final call.
- Ground truth for herdr: github.com/ogulcancelik/herdr @ ee5bfb5, `src/api/schema/agents.rs`, `response.rs`, `skills/herdr/SKILL.md`. See memory `herdr-agent-list`.
- Gap in v0.1: orchard drove one agent at a time. It had no view across targets, no signal when an agent needs a person, no review step, and no record of what it started outside Slurm (so `herdr down` and cleanup had no ownership check on plain nodes).
- Changes, one component at a time, each validated by `pytest -q` before the next:
  1. `ledger.py`: append-only `state/ledger.jsonl`. `herdr up`, `launch-herdr`, `start`, `review` write to it. `herdr down` now refuses a server orchard did not start (`--force` after a person confirms).
  2. `fleet.py` + `orchardctl fleet`: board across all ledger targets, sorted blocked > done > unknown > idle > working. An unreachable target is reported, not fatal.
  3. `orchardctl watch`: one JSON event per change of (status, state_change_seq). Runs `fleet.notify` (argv, no shell). Saves the last poll, so `watch --once` from cron reports only changes.
  4. Attention budget: `start` and `review` refuse past `fleet.max_agents` (default 16) unless `--over-budget`.
  5. `herdr review <builder>`: starts a reviewer of a different kind in the builder's cwd with a read-only prompt that ends in `VERDICT: ship | fix-first | rework`. Same kind is refused unless `--same-kind`.
  6. `orchardctl digest`: markdown in `state/digests/` with what needs the person first, plus the screens of only those agents. Kept in gitignored `state/`, because agent screens can hold secrets.
  7. `orchardctl cleanup`: dry run by default. With `--yes` it cancels or stops only owned targets, and only forgets (never stops) targets where orchard started agents on someone else's server.
- DECISION: notifications use a local command (`fleet.notify`), not `herdr notification show`. Reason: herdr shows it inside a herdr client on the target, and the person may have no client open there.
- DECISION: `watch` stays a foreground loop or a cron job. A background daemon stays out of scope.
- Offline tests: 35 passed (`pytest -q`; 18 old + 17 new).

All returned the expected JSON. The review prompt (with backticks) reached herdr as one argument and was not executed by any shell.
